Run it

These buttons run the real CLI — the same python -m pramaan.cli… a reviewer would type, with PRAMAAN_LLM_OFFLINE=1 forced, so no run spends a token or touches a network. Output below is that process's stdout, streamed. When it finishes, the ledger is re-aggregated and every number on this page updates in place.

What came in

    
The batch as it arrived, before the envelope judged
      anything — read from the DETECT rows, not from outcomes.
      That distinction is the point: the row table below is spined on
      OUTCOME, so an event that was never resolved structurally

What the planner proposed

    
One plan per distinct signature, not per event
      — a plan is memoised across every event sharing the same seven
      features, which is why 6,000 events produce a few hundred plans.
      "An LLM was called" and "the LLM wrote this plan" are different
      things, and the split below keeps them apart: a plan carries
      llm_call_ids whether the reply was usable or not, so counting
      those ids overstates the model's contribution here by 2.6×.

The recovery call

    
A Hinglish collection call, gated by the same policy
      envelope as every other action. The audio is real Sarvam TTS
      — two voices, synthesised through Sarvam's batch endpoint. The
      customer's line becomes a structured promise on the hash chain, which is
      what a recovery call is actually for. Honest scope:
      the customer's turns are a scripted transcript, not transcribed audio; the
      Sarvam STT leg is implemented and verified but is not exercised in this
      clip.

Talk to it

    
The clip above is a scripted dialogue —
      both sides are fixed text, rendered by Sarvam TTS, so the artifact is
      byte-reproducible with no key. This is not that. Hold the
      button, speak Hinglish, and one turn runs:
      your voice → Sarvam STT → the turn-policy LLM → Sarvam TTS → a reply
      you hear. The agent's words are generated against the transcript so
      far, not chosen from a list. This is the one path that cannot
      be keyless — a real conversation can't be cached before it happens
      — so it needs SARVAM_API_KEY plus an LLM key, and it
      spends money per turn.
